`Data Interface` 是专为量化对冲基金、日内高频团队、策略研发人员打造的本地行情中继与微结构复盘引擎。基于现代 **C++23** 全异步零拷贝架构，抛弃了市面传统数据商繁琐的权限割裂与单点订阅限制。

整套系统涵盖十套高度互补的专精引擎（**D1 ~ D204**），以**仅 ~5MB 的极低系统常驻开销**，提供从“全球全品种资产一键全推”到“3秒级上帝视角复盘”，再到“指定价位排单穿透”与“主力资金连续序列”的全链条量化军火库。

## 🔥 十大专精引擎：核心诱惑点深度解析

### 🌐 1. D101 —— 跨资产全域广播与“一键全推”神兽
*传统数据接口往往限制“单次只能订 50 支股票”，遇到跨市场或全市场选股策略立刻捉襟见肘。D101 彻底打破该瓶颈：*
- **全球全品种金融资产全囊括**：
  - **核心现货与板块**：主板、科创板、创业板、北交所、大盘与风格指数；
  - **场内基金与固定收益**：全市场 ETF、LOF、REITs、上万只可转债与交易所债券；
  - **场内期权全系**：上海 50/500 ETF 期权（`SO`）、深圳创业板 ETF 期权（`ZO`）、中金所股指期权；
  - **全球多市场联动**：港股/港股通、美股（NASDAQ / NYSE）、国内期货交易所主力连续合约与中金所股指/国债期货；
- **疯狂的“一键全推”广播模式**：
  - 支持传入 `universe`（如 `cn_hsj_stock` 全市场 5500+ 只股票，或 `cn_fund` 全市场 2400+ 只基金/ETF），**一条命令直接广播订阅全市场**！
  - **单连接最高承载 65,535 只标的并发流**，服务端智能分批流式分发，告别单只股票逐一订阅的繁琐逻辑。
- **独创增量合并状态机 (`reset`)**：
  - 覆盖 200 个语义字段，**只推发生变化的数值增量**，客户端就地增量合并，将网络带宽与策略机 CPU 开销降低 80% 以上。

### 👁️ 2. D3 —— 3秒级别的“上帝视角”（历史战场微结构现场还原）
*做日内 T+0、打板封单归因或高频微结构，最痛苦的就是“盘后看粗颗粒度的静态分时线，根本不知道盘中那一波急拉跳水到底发生了什么”。*
- **真正的“微观时间机器”**：
  - 按 3 秒高频切片，完整重构历史盘口的每一个切片（Tick 快照）与每一笔成交明细（Deal 明细）。
- **微观交战 100% 还原**：
  - 每一笔挂单推进、撤单诱多、大单吃单、瞬间炸板与反包回封的量价轨迹全部真实复现。
- **免去高昂的自建数据库成本**：
  - 无需自建数万元开销且极易损坏的历史 Tick 级数据库，一条标准 HTTP API 传入日期与代码，秒级返回整日微结构切片。

### 🌊 3. D2 —— 全维主力资金博弈与趋势形态中枢（识破资金真实动向）
*为趋势跟踪、形态识别、主力意图判定提供最完整的量化因子库：*
- **全天 240 根连续主力资金流序列**：
  - 提供超大单、大单、中单、小单四档分钟级真实净额序列，精准识破“指数缩量虚涨、主力暗中派发”的致命顶底背离形态。
- **情绪周期与连板梯队**：
  - 实时连板晋级、首板挖掘、炸板率统计、开板回封与封单资金强度，量化短线情绪周期。
- **龙虎榜席位与主力动向透视**：
  - 机构席位买卖净额、知名游资营业部协同作战动向全记录。
- **微观筹码变迁**：
  - 北向互联互通资金流动、股东户数集中度跃迁、大宗交易与热点板块梯队轮动。

### 🎯 4. D201 —— 盘口排队穿透与指定价位排单追踪（排单博弈神仙工具）
*排单博弈策略的终极核心痛点：挂在涨停板或关键支撑位上的单子，前面究竟还有多少人？排单能否成交？*
- **独家核心杀手锏：`price` 指定价位排队队列追踪**：
  - 指定价格（如涨停价、跌停价、指定现价）与挂单方向，**实时穿透监控该价位前方排队的单量、增量与撤单变化**，让排单成交概率与滑点推算成为可能！
- **全息队列 (`holoqueue`)**：
  - 全景穿透买卖盘口深度内的订单排队颗粒度与大单分布。

### ⚡ 5. D203 —— 极速实盘与主力委托穿透专线（高频量化与打板首选）
*延迟压制到极限，数据包原生直通：*
- **原生单据体量与档位穿透**：
  - 单据体量代码（`volume_code` 超大单/大单/中单/小单）与委托档位（`order_mmp`）原生透传，无需下游策略做二次笨重计算。
- **条件过滤订阅 (`cond`)**：
  - 支持仅推送主力大单或特定委托状态单，大幅削减下游策略进程的计算压力。
- **历史毫秒级回溯**：
  - 支持逐笔历史序列的单次翻页回溯与无缝流式衔接。

- **管理控制台与探针**：`http://127.0.0.1:9527`

### 2. Python 示例：调用 D101 一键全推全市场快照

```python
import asyncio
import json
import websockets

async def subscribe_all():
    uri = "ws://127.0.0.1:8080/d101"
    async with websockets.connect(uri) as ws:
        # 一键订阅全市场 5500+ 只标的（单命令全推）
        sub_msg = {
            "type": "snapshot",
            "universe": "cn_hsj_stock",
            "fields": ["code", "name", "price", "increase_rate_5min", "net_inflow", "limit_volume"]
        }
        await ws.send(json.dumps(sub_msg))
        print("全市场行情流已激活，实时广播接收中...")

        while True:
            msg = await ws.recv()
            data = json.loads(msg)
            print(f"收到广播推送: 包含 {len(data.get('list', []))} 只标的增量变化")

if __name__ == "__main__":
    asyncio.run(subscribe_all())
```

### 3. Python 示例：调用 D3 历史微结构上帝视角复盘

```python
import requests

# 调取指定交易日与标的的完整微结构复盘切片
resp = requests.get(
    "http://127.0.0.1:8080/d3/history",
    params={"date": "20250508", "id": "SZ002306"},
    timeout=30
)
data = resp.json()

# 包含整日 3 秒级高精分时 tick 切片与逐笔 deal 成交序列
segments = data.get("segments", [])
print(f"微结构复盘加载完成，共获取 {len(segments)} 个高精分段切片")
```

## ❓ 常见问题 (FAQ)

### Q: 为什么实测内存占用仅约 5MB？对服务器性能有何要求？
**A**: 本项目完全基于现代 C++23 编写，采用紧凑的数据结构、高效的无锁队列与就地内存解析，抛弃了一切冗余框架与重型解释器依赖。即便在最低配的 1核1G 云服务器上也能长期满负载稳定运行，CPU 与内存开销几乎可以忽略不计。

### Q: 如何将本系统的深度行情与迅投 QMT / PTrade 交易结合？
**A**: 在交易机器或内网启动本网关，策略脚本通过 WebSocket 连接本地 `8080` 端口订阅实时十档与逐笔推流，计算信号后直接调用 QMT (`xtquant`) 或 PTrade 的本地交易接口执行下单。将“极致的行情解析”与“券商原厂交易通道”分离，既能享受专业级盘口深度，又保留实盘交易的原生稳定性。
